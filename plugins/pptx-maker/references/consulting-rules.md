# コンサル資料の鉄板ルール

読むとき: create の 2 章で、設計図を書く前（4.1 の AI 判定の採点表と、6.1 の自己確認でも使う）。何のための手順書か: 承認資料の作法の一覧と、検査・自己確認の基準。承認資料の作法を 35 件（R01〜R35）にまとめたもので、ID は固定する。検査のコードもこの ID を使う。

- **区分**: 必須は、満たさないと資料の筋が通らないもの。推奨は、満たすと読みやすくなるもの。
- **検査の種類**: 3 つに分ける。**機械**は、コードで判定する（近似で警告するものは止めない。近似の機械検査（R15・R17・R20・R22・R30）は、ng にせず警告（warn）にとどめる（R15・R30 は必須だが警告どまり））。**AI**は、Claude が下の「AI 判定の採点表」に照らして判定し、結果と理由を記録する（参考であり、誤りうる）。**人**は、利用者が下の「人の確認の質問」に答えて確認する。
- **検査の場所**: 機械は `script_lint`（原稿を `lint-script` で検査）・`candidates`（案の収集と `review-page` の警告）・`check`（`build` の検査）。AI は `AI`、人は `人`。
- **利用者の追加・編集**: 利用者は、ルールの追加・編集・無効化ができる（`/pptx-maker:rules`）。この表は組み込みの 35 件の既定で、ID は固定する。
- **出典**: 調査（2026-11-18）で参照した Web の記事・書籍の要約。原典の書籍は読んでいない。「出典なし」は、公式の基準が見つからなかったもの。**文字数・要素数・語数の数値の目安は、ベンダーのブログや二次記事の慣行で、公式の基準ではない。**

## 2. ページ単位のチェックリスト

1 ページごとに、案を書く前と案を書いたあとに確かめる。

- [ ] ヘッドは結論（事実＋判断）の完全文で、30〜60 字（R13・R14）。
- [ ] 主張は 1 つ（R15）。数字は 2 つまで（人が見る。機械検査なし）。
- [ ] ヘッドの各節を証明する本体の要素が、証拠対応表で 1 対 1 に言える（R16）。
- [ ] 本体は図・表・グラフで、箇条書きだけにしない（R17）。主役が 1 つで、強調は 1〜2 か所（R22）。
- [ ] 視線は左上の題から右下の結論へ流れる（R19）。
- [ ] 数字に比較の基準（目標・前年・他案）がある（R30）。
- [ ] 棒グラフは 0 始まり。単位は 1 回。並べるグラフは同じ軸（R28・R29）。
- [ ] 出所・前提・単位が注にある（R31）。
- [ ] 論点の番号が、原稿の `論点:` に書いてある（R12）。
- [ ] 文字量がレイアウト例の密度の目安に収まる（検査なし）。
- [ ] 文字量が 700 字以内（機械は超えると警告。R25）。

## 3. ファイル全体のチェックリスト

原稿を仕上げる前と、案を書いたあとに、資料全体で確かめる。

- [ ] **縦読み**: ヘッドだけを順に読んで、結論と根拠が分かる。ページの間に、接続語（だから・なぜなら・ただし）で説明できる筋がある。筋が飛ぶところは、間のページを足すか、ヘッドを直す（R03・R07）。
- [ ] **論点の予告と回収**: サマリで論点に番号を付けて予告し、本文の各ページが `論点:` で自分の番号を示し、裏表紙（`closing`）で同じ番号で回収する。サマリの番号と裏表紙の番号が合う（R06・R12）。
- [ ] **用語の統一**: 「論点」は、サマリで予告する番号つきの 3〜6 個だけを指す。ページが答える問いは「章名」と呼び、「論点」と書かない。1 つの語に 2 つの意味を持たせない。
- [ ] **サマリと裏表紙の整合**: サマリの結論と求める決定が、最終ページ・裏表紙の結びと同じ内容になる（R01・R09）。
- [ ] **決定は 1 か所**: 求める決定は 1 つのページに書く。サマリ・決定のページ・裏表紙の 3 か所に同じ文を書かない。ほかは参照（「決定は p.2」）か、次のステップにとどめる（R18）。
- [ ] **根拠の強さ**: 結論を支える数字・事実が素材にある。なければ、前提を明記した試算か「xx」。根拠の弱いページは、ヘッドの判断を弱めるか、付録の根拠を足す（R16・R30）。
- [ ] **前提と付録**: 前提・方法・詳細表は、初出のページの注か、付録にまとめる。本編のページで同じ前提を繰り返さない（R11・R31）。付録がないときは、本編に載せない根拠が本当にないかを確かめる。
- [ ] **横の並び**: 同じ階層のページは、切り口 1 つ・粒度をそろえる（R04・R05）。
- [ ] **構成の定型**: 表紙→サマリ→本文→次のステップ→（付録）→裏表紙の順になっている（R10）。
- [ ] **現在位置**: どのページも、どの論点を読んでいるかが番号で分かる（R12）。
- [ ] **構図の偏り**: 隣り合う 3 ページで、本体の構図が違う（左右 2 分割・「大きな数字＋小さなラベル」に偏らない。デザイン方向の指針の 4 章）。

### create の 6.1 の項目

- ヘッド: `lint-script` が空。題は名詞句、ヘッドメッセージは完全文で帯に収まる。
- 数値: ヘッドの数字＝本体の数字。素材に無い数字は試算か「xx」。
- 証拠・論理: 証拠対応表のとおり本体がヘッドを証明する。縦に読んで筋が通り、論点の番号が対応する。
- 見た目: `violations` 0 件。線種と塗りの意味が全ページで同じ。隣り合う 3 ページで本体の構図が違う。

## 4. AI 判定の採点表

AI のルール（15 件）は、Claude がこの採点表に照らして、ページごと（R05・R19・R21・R24・R27・R29・R35）または資料全体（そのほか）で判定する。結果は `ok`・`warn`・`ng` と理由（どのページの何がどうか）で、`rule-review-import` で記録する。`ng` にするのは区分が必須のルールだけで、推奨のルールの `ng` は `warn` として扱う。判定は参考で、誤りうる。

### R01 答え先行（ガバニングメッセージ）（必須）

- ok: 冒頭のサマリか表紙のヘッドに、資料全体の結論が 1 文で立ち、各ページがその根拠になっている。
- warn: 結論はあるが 2 文以上に分かれる、または根拠にならないページがある。
- ng: 結論が冒頭になく、背景や経緯から始まっている。
- 証拠: 結論の文（どのページか）と、根拠にならないページの番号。

### R02 導入の型（SCQA・SCR）（推奨）

- ok: 冒頭 1〜2 ページで、状況・複雑化（困りごと）・問い・答えが順に読める。
- warn: 要素が 1 つ欠ける、または順序が違う。
- ng: 状況・複雑化がなく、いきなり答えか詳細に入る。
- 証拠: 欠けている要素の名前と、冒頭のページ番号。

### R03 縦のロジック（必須）

- ok: 上位のヘッドに「なぜ」と問うと、下位のヘッドが答えている。
- warn: 一部のページで接続が弱く、間の説明が要る。
- ng: 上位の主張を下位が支えていない、またはページ同士が無関係に並ぶ。
- 証拠: つながらない 2 ページの番号と、その間に足りない説明。

### R04 横のロジック（必須）

- ok: 同じ階層のページが、同じ切り口・同じ粒度で、演繹か帰納として並ぶ。
- warn: 1 つだけ粒度や切り口が違う。
- ng: 切り口が混在し、並びの意味が読み取れない。
- 証拠: 並びの範囲（ページ番号）と、粒度や切り口が違うページ。

### R05 MECE（推奨）

- ok: 分類が漏れなく重なりなく、切り口が 1 つである。
- warn: 重なりか漏れが 1 か所ある。
- ng: 切り口が混在し、漏れも重なりもある。
- 証拠: 分類のあるページ番号と、重なる・漏れる項目。

### R07 縦読みで筋が通る（必須）

- ok: ヘッドだけを順に読んで、結論と根拠が過不足なく分かる。
- warn: 読めるが、飛ぶ箇所や言い換えの重複がある。
- ng: ヘッドだけでは結論か根拠が分からない。
- 証拠: 飛ぶ箇所の前後のページ番号と、足りない一文。

### R08 先にタイトル（ゴーストデッキ）（必須）

- ok: 設計図の台帳のヘッドだけで骨子ができ、原稿・案の中身がそれに沿っている。
- warn: 台帳のヘッドと原稿のヘッドが一部ずれている。
- ng: 台帳がない、または中身が台帳と無関係に作られている。
- 証拠: ずれているページ番号と、台帳と原稿のヘッドの違い。

### R09 エグゼクティブサマリ（必須）

- ok: 冒頭 1〜2 ページに、結論・根拠・求める決定がそろっている。
- warn: 3 つのうち 1 つが欠ける。
- ng: サマリがない、または 2 つ以上が欠ける。
- 証拠: サマリのページ番号と、欠けている要素。

### R11 付録（バックアップ）（推奨）

- ok: 本編は主張に必要な根拠だけで、方法・前提・詳細表は付録にある。
- warn: 本編に詳細表や方法の説明が混じっている。
- ng: 付録がなく、本編が詳細で膨らんでいる。
- 証拠: 付録に回すとよい内容のあるページ番号と、その内容。

### R19 視線誘導（Z・F）（推奨）

- ok: 題（左上）から主役を経て結論（右下）へ、視線が自然に流れる。
- warn: 主役が複数あるか、結論が視線の終点にない。
- ng: 始点も終点も読み取れず、視線が散る。
- 証拠: そのページ番号と、視線が止まる要素・外れる要素。

### R21 近接・共通領域・整列・反復（推奨）

- ok: 関係の近いものが近く、端がそろい、同じ役割は同じ形である。
- warn: 一部がそろっていない、または同じ役割の形が揺れる。
- ng: 関係のないものが近接する、または配置に規則が読み取れない。
- 証拠: そのページ番号と、そろっていない要素の名前。

### R24 装飾を削る（推奨）

- ok: すべての線・図形・色が、データか構造を運んでいる。
- warn: 飾りに近い要素が 1〜2 個ある。
- ng: 影・立体・飾りが多く、データより目立つ。
- 証拠: そのページ番号と、削れる装飾の名前。

### R27 図表の選び方（推奨）

- ok: 言いたい比較（構成・項目・時系列・分布・相関）に合う図表を選んでいる。
- warn: 読めるが、より合う図表がある。
- ng: 比較の種類と図表が合わず、主張が読み取れない。
- 証拠: そのページ番号と、比較の種類・使っている図表・合う図表。

### R29 軸・単位・凡例・ラベル・同一スケール（推奨）

- ok: 単位が 1 回示され、要素に実数ラベルがあり、並べるグラフの軸が同じである。
- warn: 単位かラベルが一部欠ける、または軸が違う。
- ng: 単位がなく、数字の意味が読み取れない。
- 証拠: そのページ番号と、欠けている単位・ラベル・軸。

### R35 読み手への適合（必須）

- ok: 主役の図表が、読み手の知らない用語や前提を飛ばさずに読め、「読み手にさせたいこと」が設計図の目的と求める決定につながっている。
- warn: 読み手が知らない用語の説明が足りない、または既知の話に紙面を使いすぎている。
- ng: 読み手の前提知識では読み取れない、または「読み手にさせたいこと」が目的・求める決定とつながらない。
- 証拠: そのページ番号と、読み手の前提知識（設計図の文）に合わない用語・図表・行動の名前。

## 5. 人の確認の質問

人のルール（3 件）は、案の選択ページで利用者が確認する。次の質問に答える。

### R32 数値・前提の正しさ（必須）

資料の数字（金額・件数・日付）と試算の前提は、事実と社内の基準に合っていますか。素材にない数字は「xx」のままではありませんか。

### R33 機密情報の確認（必須）

社外秘・個人情報・取引先名などが含まれていませんか。含めるなら、配布先に見せてよい内容ですか。

### R34 決定事項と承認を求める相手（推奨）

求める決定は 1 つに特定されていますか。承認する権限のある相手に向けた内容ですか。
