# 型と自由設計（案の作り方）

読むとき: create の 3 章で、案を書く前。何のための手順書か: 見本をどう使い、案（R）をどう書くか。`assets/components/` の 11 本（表紙・裏表紙・本文の土台・グラフ 6 種・表 2 種）と絵の見本 5 本は**見本**で、案はすべて自由設計（`NN-R1`〜`NN-Rn`。`Rk` が方向 k）。

## 見本の使いどころ

| 内容 | 近い見本 |
|---|---|
| 表紙・裏表紙 | `cover`・`closing` |
| 文だけの説明 | `text` |
| 数値のグラフ | `bar`・`hbar`・`line`・`stacked`・`pie`・`waterfall`（主張に合う種類を選ぶ） |
| 案の比較（評価軸×案） | `options` |
| 対応一覧（対策・課題・リスク） | `actions` |

## 案（R）

全ページ（表紙・区切り・裏表紙も）で、ファイルは設計図に `- デザイン方向の候補:` の行があれば `slides/NN-R1.html`〜`NN-Rn.html`（方向の数。`Rk` が方向 k）、なければ `NN-R1.html`〜`NN-R3.html`（2〜3 案）。見本をそのままコピーせず、そのページの主張（ヘッドメッセージ）をいちばんよく見せる構成を、`pp-*` の部品（絵 `pp-picture` も使える）で設計する。案どうしは、色ではなく構成を変える（候補の行がないときは主役の種類まで変える）。グラフだけは `data-chart` で書く。守ること・考え方は、同じ 3 章で読む「自由設計（R）の指針」。構図の方向（デザイン方向）の選び方と、見本をなぞらない注意も、同じ 3 章で読むデザイン方向の指針にある。

- `data-variant="案の特徴"` を付ける。デザイン違い（`-d2`・`-d3`）は作らない。
- `check` が違反 0 件になること。
- 区切りのページ（`data-layout="divider"`）は本文のレイアウトを使う。題を置くなら本文の題と同じ大きさにし、置かないなら題の規約（`chromeSpec`）は検査されない。
