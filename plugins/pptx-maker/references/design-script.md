# 設計図と原稿の書き方

読むとき: create の 1 章（入力とテンプレート）と 2 章（設計図・題とヘッドメッセージ・原稿）に入る直前。何のための手順書か: 入力の受け取り方と、設計図・原稿の書き方。コマンドは SKILL.md にある（`RUN <サブコマンド>` の形）。

## 入力とテンプレート

**入力**
- 入力は、チャットの文章・テキストファイル・PPTX・Excel・PDF のパスか本文で受け取る。
- 入力は形式ごとに読む（PPTX は `RUN pptx-extract "<pptx>"` が標準出力に出す Markdown で、題・本文・表・グラフの数値が入り、ノート・非表示スライド・画像・SmartArt は入らない。読めない PPTX は終了コード 2 で、パスワード付きは利用者に外してもらう。Excel は `anthropic-skills:xlsx`、PDF は `anthropic-skills:pdf`。文章・テキストはそのまま）。`input.md` には、出典（ファイル名と、ページ・シートの位置）を付ける。
- 入力が PPTX のとき、図や表は、文字と数値から描き直すのを基本とする。画像のまま持ち込むのは、設計図に図ごとに書いたときだけ。

**テンプレート**
- テンプレートで使うのは表紙・本文・裏表紙のレイアウトだけ。フォントは変わらない。配色は、設計図に色を書かなければテンプレートの色に従う（`init` の結果の `template_accents` が、その色。設計図に書く色の参考にする）。
- テンプレートを指定したら、`layout_map`（表紙・本文・裏表紙に当てたレイアウト）を表で見せる。

**色**
- 基調色・強調色は**最初には決めない**: 利用者が指定したときだけ設計図に書き、なければテンプレートの色（それもなければ既定）で進める。
- 配色は、案の選択ページの「配色」で、全ページの案の色を見ながら変えられる（5 章）。

**作業フォルダ**
- `<出力先>` が UNC（ネットワーク共有）だと測定が止まるので、ローカルのドライブで使う。
- `init-overwrite` は、ファイルは消さない。渡さない設定は前の値を残す。実行すると権限の確認が出るが、出なくても（許可済みでも）、チャットで承認を得る前には実行しない。
- `init-overwrite` のあとは、`notes` を伝え、`slides/` に残る前の案は確かめてから消す。
- 専用の仮想環境の作成元は、venv と ensurepip のある Python 3.12 以上（create の 0 章）。

## 設計図

入力が複数あっても元の資料の並び順には従わず、論点に組み直して統合する。先に設計図で各ページの題・ヘッドメッセージと論理を決め、原稿に写す。

1 枚物なら資料全体と台帳を省く。書く前に、鉄板ルール R01〜R35 とチェックリスト（検査の種類は機械・AI・人の 3 つ）を読む。

- 資料全体に、**目的**（この資料で何を達成したいか）・**読み手**（役職と、この資料で何を決める立場か）・**読み手の前提知識**（知っていること・知らないこと）・**求める決定**を必ず書く。空欄や欠けは `lint-script` がエラーにする（値は項目名と同じ行に書く。`<!-- -->` の中は書いたことにならない。1 枚物は対象外）。聞いても分からないときは推測せず、利用者に確かめる。
- **ガバニングメッセージ**（資料全体の結論）を 1 つ立て、各ページのヘッドをぶら下げる。**論点**は 3〜6 個に番号を付け、冒頭で予告し裏表紙で回収する。「論点」はこの番号つきの議題だけを指し、ページが答える問いは「章名」と呼ぶ。求める**決定は 1 か所**に書き、ほかのページは参照にとどめる。前提・方法・詳細表は、初出の注か付録に置く。
- 台帳（No・ヘッド・文型・上位への集約・接続語・本体の型・論点）を先に作る。ヘッドを縦に通読して「だから／なぜなら」で繋がり、横の並びは切り口 1 つ・粒度をそろえる。
- **デザイン方向**は、設計図ができたあとの 3 章で候補の名前だけを利用者に確かめ、`- デザイン方向の候補: R1=名前, R2=名前, …` として書き足す。どの方向にするかは、`review.html` の「方向」で見てから決め、取り込みが `- デザイン方向: <名前>` に書く。
- 資料全体に**基調色**（1 色）と**強調色**（1〜2 色。カンマ区切り）を書く（`基調色:`・`強調色:`。なければテンプレートの色）。
- ページごとに、題・ヘッドメッセージ・文型・型か自由設計か・**主役の図表**・**読み手にさせたいこと**（この 2 つは必須）・チャートタイトル・レイアウト記述（軸・エリア・強調の 1 点）・証拠対応表・注記を書く。

- 利用者が「ルールを足したい／直したい／消したい／無効にしたい」と頼んだら、`/pptx-maker:rules` を案内する（この手順では扱わない）。

## 題とヘッドメッセージ

細則は、書く前に読む題とヘッドメッセージの規則。題は名詞句 20 字以内で主題だけ。ヘッドメッセージは事実＋判断を言い切る完全な 1 文（30〜60 字、帯に収める）。「A。B」・数え上げ・体言止め・ダッシュ（—）・自己言及は禁止。決定を求めるページだけ、メッセージボックスに「〜の可否」を 1 行。

## 原稿

スライドごとに、次の項目を書く。
- 全スライド: `layout`（`cover|content|diagram|table|chart|divider|closing`。先頭は `cover`）・`題`・`ヘッドメッセージ`・`章名`（答える問い）・`本文`・`図表`（型か「自由設計」か「絵/<種類>」と理由）。
- 本文のスライド: `主役の図表`・`読み手にさせたいこと`・`論点`（このページが属する論点の番号。`論点: ①` のように書く。サマリは `①〜④`）。
- 要るときだけ: `出典`・`判断の枠`。
- `lint-script` は、終了コード 0 のときも、題の抜けの案内（`案内:` で始まる行）が出ることがあるが、エラーではない。
