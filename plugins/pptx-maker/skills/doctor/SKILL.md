# pptx-maker doctor: 環境を点検する

pptx-maker が動く環境（専用の仮想環境・ライブラリ・chromium・フォント）を、何も変えずに点検し、結果を項目ごとに伝える。足りないものは、利用者の承認を得て導入できる。インストール中の版が最新かも分かる。

## 用語
| 用語 | 意味 |
|---|---|
| 専用の仮想環境 | `${CLAUDE_PLUGIN_DATA}` の下に作る、pptx-maker だけの Python の環境 |
| chromium | スライドの HTML を測るブラウザ（数百 MB） |
| `[OK]`・`[NG]`・`[任意]`・`[情報]` | 出力の行の印。`[NG]` は動かない原因、`[任意]` はなくても動くもの、`[情報]` はプラグインの版の行 |

## 全体の流れ
| 手順 | やること | 終わりの目印 |
|---|---|---|
| 1 点検する | `doctor` を実行する | 出力と終了コードを受け取った |
| 2 結果を伝える | 終了コードに応じて、項目ごとに伝える | 結果を伝えた |
| 3 導入する | 専用の仮想環境がない・足りないとき（導入が必要なとき）、承認を得て導入する | 導入して点検し直した（導入しないときは、伝えて終わる） |

## 手順

### 手順1: 点検する
目的: 環境の状態を、何も変えずに調べる。

環境を点検する（何も変えず、項目ごとの結果を出す）。
`python "${CLAUDE_PLUGIN_ROOT}/run.py" --data "${CLAUDE_PLUGIN_DATA}" doctor`

### 手順2: 結果を伝える
目的: 出力を、項目ごとに利用者へ伝える。

- 終了コード 0（`[NG]` なし）: 出力の行を項目ごとに伝える。
  - `[OK]`: 一言で済ませる。
  - `[任意]`: BIZ UDPゴシック（既定のフォント）が未導入。PowerPoint で折り返しがずれることがあるだけで、使わなくても動く。
  - `[情報]`: プラグインのバージョンの行。かっこの中の文言で伝え方を分ける。
    - 「（最新です）」: 最新と伝える。
    - 「（GitHub のマーケットプレイスに登録していないため、最新かは確認しません）」: 最新かは確認していないと伝える。対処はない。
    - 「（最新のバージョンを確認できませんでした: …）」: 理由と、次の行の対処（ネットワーク・github.com への通信の確認）をそのまま伝える。更新の手順は案内しない。
    - 「（GitHub に v… があります）」: 次の 3 行の更新の手順（`/plugin marketplace update` → `/plugin update` → Claude Code を開き直す）を伝える。
- 終了コード 3（`[NG]` あり。OS・実行環境・保存先、または専用の仮想環境がない・足りない）: 出力の `[NG]` の項目と、「→」の対処を伝える。`[情報]` のバージョンの行も、上の伝え方で伝える。仮想環境がないときは、出力に BIZ UDPゴシックの行は出ない（導入したあとの `doctor` で出る）。
- 終了コード 2（引数の不備。`--data` が置き換わっていない・絶対パスでない、など）: 標準エラーのメッセージを伝える。

### 手順3: 導入する
目的: 専用の仮想環境がない・足りないとき（導入が必要なとき）、利用者の承認を得て、仮想環境・ライブラリ・chromium を入れる。

利用者に「`${CLAUDE_PLUGIN_DATA}` の下に専用の仮想環境と chromium（数百 MB）を入れてよいか」を確かめ、承認を得てから、導入する（ネットワークから取得する）。
`python "${CLAUDE_PLUGIN_ROOT}/run.py" --data "${CLAUDE_PLUGIN_DATA}" setup --yes`
- 取得に時間がかかる。バックグラウンドで実行して完了の通知を待つ（上限 10 分。超えたら止めて出力を報告する）。
- 失敗（0 以外の終了コード）したら、出力をそのまま利用者に伝えて止める。自動で再試行しない（原因を直したあと、利用者が頼んだときに 1 回やり直す）。
- 成功したら、`doctor` をもう一度実行して結果を伝える（手順1・2）。
