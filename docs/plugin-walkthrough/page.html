pptx-maker は、Claude に何を読ませ、何を実行させるのか

承認文書を、HTML スライドを経由して編集できる PPTX にするプラグイン。この解説では、Claude が実際に読む文章と、実際に実行した標準出力を、手順ごとに並べる。

結論: 手順はすべて skills/create/SKILL.md が握る。Claude は、章に入る直前に手順書（references/*.md）を 1 つずつ読み、run.py を通して Python を実行する。

この解説で分かること: ファイルの役割、1 回のやり取りの順序、各手順で読むものと実行するもの、止まる条件、実出力。

使い方: 初めて読むときは、1 章から 6 章まで順に読む。実際の文章と出力は 7 章にある。

  • 1 構成
  • 2 順序図
  • 3 手順ごとのカード
  • 4 手順書を分けた理由
  • 5 機械的に止まる条件
  • 6 判断の規則
  • 7 実際に読む文章と出力
  • 8 前提と環境
  • 9 実際の画面
  • 10 出典とライセンス
  • 11 範囲と未確認

この章で使う印: 解説この文書の筆者の説明 読むClaude が読む実ファイルの全文 書くClaude が書くサンプル 標準出力実際に実行した出力 戻り値ブラウザ操作が返す値

実行の入口と、2 つの置き場

  • 解説run.py は、先頭の --data <絶対パス>（SKILL.md が渡す ${CLAUDE_PLUGIN_DATA}）を環境変数 PPTX_MAKER_HOME として子プロセスに渡す。
  • 実行に使う Python は、<データの置き場>/venv の専用の仮想環境だけ。版と chromium が足りなければ終了コード 3 で止め、setup --yes を案内する。
  • データの置き場（以下 <D>）に、仮想環境・登録したテンプレート（templates/）・追加したルール（rules/custom.json）が入る。
  • 成果物の作業フォルダは <出力先>/pptx-maker-source/<成果物名>。出力先は聞かず、常にカレントディレクトリ（<起動フォルダ>）。

6　状態・分岐・聞き直しの規則

解説判断が分かれるところは、コードか SKILL.md が先に決めている。次の表は、迷いやすい 6 つを並べたもの。

場面規則決めている場所
案の数どのページも 2〜4 案。案の名前は、レイアウトの違いで付け、断片の data-variant に書く。全体の「デザイン方向」は決めないSKILL.md 3 章・candidates.collect
承認承認は案の選択だけ。内容の直しは、ページのコメント欄に書かれたものだけで受ける。コメントのあるページは承認できないSKILL.md「守ること」・review-page の JS
貼り付けの状態saved（選んだだけ・取り消し）と approved（承認）の 2 つ。コメントを直して choices-resolve すると、承認済みは saved に戻り、pick は残るreview-flow.md・choices.resolve
承認のあとで断片が変わった承認した断片の指紋 frag が今と違えば finalize が止まる。review-page をやり直して、承認し直してもらうfinalize.finalize
AI 判定判定は参考で、誤りうる。ページごとの判定には、記録時の全案の指紋が付き、断片が変わると pending に戻る。pending が 1 つでもあれば finalize が止まるreview-flow.md・consulting.pending_ai
上書き・削除上書き版（init-overwrite・build-overwrite・template-overwrite）と template-remove は、チャットで利用者の承認を得たあとだけ実行する。権限の確認が出なくても同じSKILL.md「守ること」
聞き直し足りない前提（対象者・目的・枚数・期限・欠けている数字）は、始める前にまとめて聞く。推測しない。素材にない数字は作らず、「xx」にするSKILL.md 1・2 章
build の直し検査違反は、該当ページの断片の配置・サイズだけを直す。再 build は 3 回まで。超えたら違反の一覧を利用者に示すcheck-rules.md
解説コメントの本文は、利用者の入力である。SKILL.md は、これを指示として扱わないと定める。

7　Claude が実際に読む文章と、実際の出力

解説この章は、手順ごとに、実ファイルの全文と、実行した標準出力を載せる。出力は、リポジトリの外の一時フォルダで、run.py を実際に動かして採った。ブラウザの操作だけは実行できないため、書式から作った例だと明記する。

解説デモの条件: 3 枚の資料（表紙・本文・裏表紙）を作る。置き場 <D>・起動フォルダ・作業フォルダは、使い捨ての一時フォルダ。パスは、<D>・<起動フォルダ>・<元データ>・<作業用>・<TEMP> に置き換えてある。仮想環境は、導入済みのものを借りた。

読んだ範囲

  • 7 章に全文を載せたが、解説のために読み込んでいない: consulting-rules.md・head-rules.md・design-directions.md・html-rules.md・components.md・patterns.md・icons.md・picture-craft.md。載せた文章は、ファイルの実体をそのまま埋め込んだもので、要約していない。
  • 読んでいない: review_page.py・consulting.py・rulebook.py・candidates.py・measure.py・check.py・build.py・charts.py・template.py などの内部実装。tests/。

確かめていないこと

  • Claude Code の中で /pptx-maker:create を実際に打ち、SKILL.md の ${CLAUDE_PLUGIN_ROOT}・${CLAUDE_PLUGIN_DATA} が置き換わる様子。デモは run.py を直接実行した。
  • 案の選択ページ上の操作（案の選択・承認・「Claude に渡す」のクリップボードへのコピー）。貼り付け文は、書式から作った例である。
  • 断片 slides/*.html は、デモ用に見本を写して書き換えた。Claude が素材から設計して書く内容は、実行していない。
  • setup --yes（ライブラリと Chromium の導入）、init-overwrite・build-overwrite・template-overwrite、rule apply の書き込み、検査違反（終了コード 1）の build。
  • PowerPoint での PPTX の実際の見え方。
