## 概要
### 入力
- 依頼文: 「このリポジトリのSKILL.mdを人間読んで理解できる形にしつつ、シンプルな形にしたい。ただし、現在のmainと同じ動作になることが必須である。」
- 対象リポジトリ: `D:\claude\local-repo\pptx-maker`（Windows 専用の Claude Code プラグイン `pptx-maker`）。基準は main のコミット `3d149a1`。参考資料のファイルは指定されていない。

### 目的と対象
- `plugins/pptx-maker/skills/` の 4 つの SKILL.md（create・rules・template・doctor）をすべて簡素化の対象にする。
- SKILL.md を、人が読んで理解できる内容にし、そのうえでシンプルにする。
- 「読みやすい」とは、人が読んで理解できる内容であることを指す。短さと理解できることが衝突するときは、理解できることを優先する。
- 簡素化の前後で、動作は今の main と同じでなければならない（必須条件）。

### 簡素化のやり方
- 重複する表と、見出しと実質同じ内容の「目的:」行を削る。
- 動作の指示（利用者への伝達・読むファイルなど）を含む「目的:」行は、削らずに内容を残す。
- 意味を変えない範囲で、言い回しを短くする。
- 注意の集約は、既にある「守ること」の節（create・rules・template）に、2 か所以上で重複している注意だけを集める。
- doctor には「守ること」の節を新設しない。
- 1 か所にしか出ない注意と、テストが固定している文は、手順に残す。
- 章の統合・番号の振り直し・見出しの改名をしてよい。
- 手順の内容を `references/` へ移さない（Q2 の選択肢 D「手順を `references/` へ移す案」は選ばれていない）。
- frontmatter（`name`・`description`・`compatibility`・`disable-model-invocation`・`allowed-tools`）は変更しない。

### 流れ
- 作業はブランチを切って行い、コミットし、PR まで作る。
1. 変更前の動作要素を、4 つの SKILL.md から一覧にする（作業用のファイルに書く）。
2. 章番号・見出しを参照している箇所を、リポジトリ全体から洗い出す。
3. 4 つの SKILL.md を簡素化する。章を組み替えたときは、2 で洗い出した参照を同じ変更で直す。
4. 変更後の SKILL.md から同じ一覧を作り、変更前の一覧と照合する。
5. `pytest` と `ruff` を実行する。
6. 別のエージェントに変更前後の SKILL.md の全文を渡し、動作が変わる所を探させる。
7. 日本語のコミットメッセージで、既存の履歴（`docs: … (#N)`）に合わせる。ブランチと PR は、`~/.claude/reference/git-flow.md` に従う。PR の本文に、確認結果と、変更前後の長さ（バイト数・行数・表の数）を載せる。

### 動作要素の一覧
- 一覧の項目は、コマンド、終了コードごとの対処、承認が要る場所、読むファイルとその順、`AskUserQuestion` を使う場所に加えて、条件分岐（ある状況でだけ実行する手順）、利用者への発話の指示、注意・禁止事項（どの手順に効くか）とする。
- 一覧は、スクラッチパッドのファイルに書き、PR の本文には要約と照合の結果を載せる。

## 受入条件
- `pytest` と `ruff` が、変更前と同じく通る。
- `tests/test_docs.py` と `tests/test_overwrite_subcommands.py` が固定する語・見出し・コマンドの順序は、変更前と同じに保つ。
- 4 つの SKILL.md の frontmatter は、変更前後の差分が空である。
- 変更前後の動作要素の一覧に、欠落・追加・順序の違いがない。
- 章番号・見出しを参照する箇所（`references/`・`assets/sample/design.md`・rules と template の SKILL.md・`CLAUDE.md`・`README.md`・`docs/`）に、実在しない章への参照が残らない。
- 別のエージェントによる前後の比較で「動作が変わる」と指摘された箇所は、すべて、直されたか、動作が変わらない根拠が PR の本文に書かれている。
- 合否は動作の同じさで決める。長さ（バイト数・行数・表の数）は、変更前後を PR に載せる目安であり、合否の基準にしない。
- 「読んで理解できる」ことは、PR のレビューで利用者が判断する。
- PR の本文に、理解しやすさのために直した主な点（削った表・「目的:」行、まとめた注意）を、章ごとに書く。
- ブランチ・コミット・PR が作られている。

## 非目標
- `references/` の内容の追加・削除・移動。章番号の参照を直すことだけは、してよい。
- テスト・コード（`plugins/pptx-maker/` の Python）の変更。
- SKILL.md の機能・手順・コマンド・承認の関門の追加や削除。
- 削減率の目標を決めること。

## リスク
- SKILL.md は Claude が読んで動く文書であり、コードのテストでは同じ動作を証明できない。3 つの確認（`pytest`・一覧の照合・別エージェントの比較）を重ねても、見落としはありうる。別エージェントの比較は、読み手のモデルの挙動を再現するものではなく、弱い検証である。
- 注意を「守ること」にまとめると、手順だけを読んだときに注意を見落とす可能性がある。2 か所以上で重複している注意に限って、これを抑える。
- 章を組み替えると、章番号・見出しを参照する箇所のずれが、静かに読む順を変えるおそれがある。洗い出しと、実在しない章への参照が残らないことの確認で抑える。
- 表と「目的:」行の削除が、他に書かれていない情報の削除になるおそれがある。削った表の内容が残る場所を、PR の本文に書く。
