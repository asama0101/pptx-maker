## 概要
pptx-maker に、既存の PPTX を読んで Markdown にするサブコマンド `pptx-extract` を足す。create スキルの PPTX 入力を、外部スキル（`anthropic-skills:pptx`）から、この新コマンドに置き換える。

### 入力
依頼文: 「PPTX を取り込めるようにしたい」。現状、create スキルは PPTX を入力に受け付けるが、Claude が外部スキルで読んで `<元データ>/input.md` に書き写す方式で、pptx-maker 自身に PPTX を読むコードがない（`python-pptx` は書き出し用）。参考資料はなし。

- 目的: 既存 PPTX を、設計図・原稿を作る元資料（作り直しの入力）にする。HTML 側が正本という方針は変えない。
- 対象: 任意の PPTX（pptx-maker 製に限らない）。
- 直す点: プラグイン内蔵の抽出コマンドを作ること。題・本文（階層つき）・表・グラフの数値を、下の「読む範囲」について決定的に読むこと（「漏れなく」はこの範囲の中の話）。

## 流れ
1. 利用者が PPTX のパスを渡す。create スキルが `pptx-extract <pptx>` を実行する。専用 venv で動かす点、`run.py` 経由で呼ぶ点は、ほかのサブコマンドと同じ。`cli.py` にサブコマンドとして足す（実装の置き場所は計画で決める）。作業フォルダは取らない（`paths.resolve_work` の対象外）。PPTX が複数あるときは、Claude が複数回実行する。
2. コマンドは python-pptx で読み、成功すれば終了コード 0 で Markdown を標準出力へ出す。文字コードは UTF-8 に固定する。`--out` は作らない。
3. Claude が出力を、他の入力と合わせて `<元データ>/input.md` にまとめる（出典の付け方・統合は従来どおり Claude が行う。出力の見出し `## スライド N` とファイル名が出典になる）。
4. 以降は既存の流れ（設計図 → 原稿 → …）。

### 読む範囲と出力の形（Markdown）
- 先頭に PPTX のファイル名を 1 行（`# <ファイル名>`）で出す。
- スライドごとに `## スライド N: <題>`。N は PowerPoint 上の元の通し番号（非表示スライドは `sld` の `show="0"` で判定して読まないので、番号が飛ぶことがある）。題はタイトル・中央タイトルのプレースホルダーの文字で、複数段落は半角スペースでつなぐ。なければ「（題なし）」。題の図形は本文からは除く（二重に出さない）。
- 本文は、文字を持つ図形（プレースホルダー・テキストボックス・四角形などの図形の中の文字）を、XML の順で出す（座標順への並べ替えはしない）。グループは再帰して、グループ内の図形・表・グラフも同じ規則で読む。表・グラフは、図形と同じ XML の順の位置に出す。空の段落は出さない。
- 箇条書きは階層を保つ（`- ` とインデントで表す。番号付きも `- ` に揃える）。
- 表は Markdown の表にする。セルの結合は、結合元の値を 1 回だけ出し、残りを空にする。セル内の改行は `<br>`、`|` は `\|` にする。
- グラフは `[グラフ: <種類>]` の次に Markdown の表を出す。行がカテゴリ、列が系列。値はグラフに保存された数値のまま（表示形式は反映しない）。種類は日本語名で、対応表にない種類は python-pptx の名前のまま出す。カテゴリのない種類（散布図・バブル）は、系列ごとに X, Y の組を表にする。系列が 0 件、または値がすべて空のグラフは、エラーにせず「[グラフ: 値を読めませんでした]」と出して続ける。
- 読まないもの: スピーカーノート、非表示スライド、スライドマスター・レイアウト上の文字、スライド上のヘッダー・フッター・スライド番号・日付のプレースホルダー、コメント、画像、SmartArt、書式（太字・色・フォント）、ハイパーリンク、グラフのタイトル。create スキルの「図は文字と数値から描き直す」は変えない。

### 読めない PPTX
次の 5 分類は、読めなかった理由を日本語で標準エラー出力に出し、終了コード 2 で止まる。標準出力には何も出さない（読み切ってから 1 回で出す）。理由は、分類ごとに違う文言にする。

1. 拡張子が `.pptx` でない（大文字小文字は区別しない。`.ppt`・`.potx`・`.pptm` を含む）
2. パスが存在しない、またはフォルダである
3. 空ファイル
4. パスワード付き（暗号化）
5. 壊れている（zip でない・python-pptx が開けない）

4 と 5 は、python-pptx が開けなかった例外を 1 か所で受けて扱う（暗号化かの判定は、ファイルの先頭が OLE 形式かで行う）。4 のメッセージには「パスワードを外すか、PowerPoint で保存し直してください」と添える。ファイル単位の失敗は、ここだけである。

### create スキルの変更
`skills/create/SKILL.md` の 32〜33 行（入力を既存のスキルで読む節と、「入力が PPTX のとき」）で、PPTX は `anthropic-skills:pptx` ではなく `pptx-extract` で読むと書く。27 行の入力の列挙に「PPTX」と出てくる箇所は、入力の種類の列挙なので、そのまま残す。外部スキルへ戻す経路は残さない。

## 受入条件
1. 固定の PPTX（題・階層つき箇条書き・表・グラフ・グループを含む）を `pptx-extract` に渡すと、「読む範囲と出力の形」の節のとおりの Markdown が標準出力に出る。pytest が、期待する Markdown との突き合わせで確かめる。
2. 題のないスライドは「（題なし）」と出る。非表示スライドを飛ばしても、スライド番号は元の通し番号のままである。題の文字は本文に重ねて出ない。
3. 「読まないもの」の各項目（ノート・非表示スライド・マスター文字・スライド上のフッター・コメント・画像・SmartArt・グラフのタイトル）は、出力に現れない。テストは、python-pptx で作った PPTX にこれらを入れて検査する（python-pptx で作れないもの＝コメント・SmartArt は、XML を直接足すか、検査から外してリスクに残す）。
4. 読めない PPTX の 5 分類は、それぞれ終了コード 2 と、分類ごとに違う日本語のメッセージ（標準エラー出力）で止まり、標準出力は空である。パスワード付きのテストデータは、OLE 形式の先頭のバイト列を持つ固定ファイルで作る。
5. pytest で、題・階層・表（結合・改行・`\|` を含む）・グラフ（棒・散布図・値が空）・グループ内の文字と表・題なし・非表示の番号・先頭のファイル名行・読めない 5 分類の各ケースが検査される。テスト用の PPTX は python-pptx で生成する。`cli.main` を直接呼んで、終了コードと標準出力・標準エラーを見る。ruff が通る。
6. create スキルの PPTX 入力の記述が新コマンドになり、プラグインと README（`plugins/`・`README.md`・`CLAUDE.md`）に `anthropic-skills:pptx` への言及が残らない（`grep` で確かめる。`docs/superpowers/` は対象外）。`tests/test_docs.py` が通る。
7. README.md の PPTX 入力の説明（作成後の直しの節の近く）と、CLAUDE.md のコマンドの説明に、`pptx-extract` と、読む範囲・読めないときの終了コードが書かれる。

## 非目標
- PowerPoint で直した内容を HTML 側へ戻すこと（「手直しの戻し」。現状の方針のまま、取り込まない）。
- テンプレートとしての取り込みの強化（`template-import` は変えない）。
- 画像・図の素材としての取り込みと、画像内の文字（OCR）。
- スピーカーノート・非表示スライド・マスター上の文字・コメント・グラフのタイトルを読むこと。
- SmartArt・埋め込みオブジェクト（OLE）・数式の文字、書式、ハイパーリンク、グラフの表示形式を読むこと。
- 座標順への並べ替え、巨大な PPTX の枚数制限、外部リンクをたどること。
- `--out`（ファイルへの書き出し）。
- pptx-maker 製 PPTX だけの特別扱い（`pp-*` 部品の読み戻し）。
- `.ppt` の自動変換、`.potx`・`.pptm` を読むこと。

## リスク
- 画像や SmartArt だけで図を作った資料では、出力がほとんど空になり、create スキルの「図は文字と数値から描き直す」が成り立たない（利用者が本文の文章で補うことになる）。
- 図形の重なりや並びによっては、XML の順と見た目の順が違い、本文の順序が崩れる。題がタイトルのプレースホルダーでなく通常のテキストボックスにあるスライドは「（題なし）」になり、題の文字は本文として出る。
- スピーカーノートや非表示スライドに重要な内容がある資料では、それらは入力に載らない（利用者が選んだ範囲）。
- グラフの数値は表示形式（%・通貨・桁区切り）を失い、複合グラフ・複数階層のカテゴリは、python-pptx が返す形のままになる。表の入れ子は読まない。
- 数百枚の PPTX では出力が大きくなり、Claude が `input.md` にまとめるときにコンテキストを圧迫する（枚数の上限は決めない）。PPTX の文字・数値はそのまま `input.md` に残るので、機密を含む資料は、その作業フォルダの扱いに注意する。
- パスワード付きの資料は、利用者が手で外すまで読めない。外部スキルへ戻す経路は残さない。
- python-pptx の版を上げると、グラフの種類名や例外の型が変わりうる（`requirements.txt` は `==` 固定で、テストが変化を検知する）。
